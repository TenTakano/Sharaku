# Sharaku 仕様書 - 全体概要

## 1. アプリ概要

Sharaku はローカルの画像フォルダを「作品」として管理・閲覧するデスクトップアプリケーション。
Tauri 2（Rust バックエンド）+ Svelte 5（フロントエンド）+ SQLite（データベース）で構築されている。

ユーザーは「ライブラリ」を作成し、その中に作品を登録して管理する。
作品は現在フォルダ単位で管理され、フォルダ内の画像をビューアで閲覧できる。

---

## 2. データモデル

最新のマイグレーションは Migration 004。

### libraries（ライブラリ）

作品を束ねる最上位の管理単位。

| カラム     | 概要                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| id         | テキスト形式の主キー                                                               |
| name       | ライブラリ名（必須）                                                               |
| path       | ライブラリルートのパス。full モードではフォルダパス、metadata_only モードでは null |
| is_active  | 現在アクティブなライブラリかどうか（デフォルト: 0）                                |
| created_at | 作成日時                                                                           |

### works（作品）

ライブラリに属する個々の作品。

| カラム                  | 概要                                                     |
| ----------------------- | -------------------------------------------------------- |
| id                      | 自動採番の整数主キー                                     |
| library_id              | 所属ライブラリへの外部キー                               |
| title                   | 作品タイトル（必須）                                     |
| path                    | 作品フォルダのパス（必須）                               |
| type                    | 作品種別。'image', 'pdf', 'archive', 'folder' のいずれか |
| page_count              | ページ数                                                 |
| thumbnail               | サムネイル画像（バイナリ）                               |
| created_at / updated_at | 作成・更新日時                                           |
| artist                  | 作者                                                     |
| year                    | 年                                                       |
| genre                   | ジャンル                                                 |
| circle                  | サークル                                                 |
| origin                  | 出典                                                     |

- ライブラリ内でパスは一意（library_id と path の複合ユニーク制約）
- 現在の実装では type='folder' のみ使用。他の種別はスキーマ定義のみ存在

### tags（タグ）

作品に付与するタグ。ライブラリごとに管理される。

| カラム     | 概要                       |
| ---------- | -------------------------- |
| id         | 整数主キー                 |
| library_id | 所属ライブラリへの外部キー |
| name       | タグ名（必須）             |
| category   | タグカテゴリ（任意）       |

- ライブラリ内で名前とカテゴリの組み合わせは一意

### works_tags（作品タグ関連）

作品とタグの多対多リレーション。work_id と tag_id の複合主キー。

### settings（ライブラリ設定）

ライブラリごとの設定をキーバリュー形式で保存する。

| カラム     | 概要                   |
| ---------- | ---------------------- |
| library_id | ライブラリへの外部キー |
| key        | 設定キー（必須）       |
| value      | 設定値（必須）         |

- library_id と key の複合主キー

### app_settings（アプリ設定）

アプリ全体の設定をキーバリュー形式で保存する。テーマやバナーの自動クローズ秒数などが格納される。

| カラム | 概要               |
| ------ | ------------------ |
| key    | 設定キー（主キー） |
| value  | 設定値（必須）     |

### playlists / playlist_items（プレイリスト）

スキーマは存在するが、現時点では未実装。

## 3. 画面構成と遷移

アプリの画面状態は `currentView` によって管理される。

### 画面一覧

| currentView  | 画面                 | 概要                                     |
| ------------ | -------------------- | ---------------------------------------- |
| library      | 作品グリッド         | 作品一覧をグリッド表示（デフォルト画面） |
| viewer       | 作品ビューア         | 選択した作品の画像を閲覧                 |
| settings     | ライブラリ設定       | アクティブなライブラリの設定変更         |
| import       | 単一フォルダ取り込み | フォルダを1つずつ作品として登録          |
| bulk-import  | 一括取り込み         | 複数フォルダをまとめて作品として登録     |
| add-library  | ライブラリ追加       | 新しいライブラリを作成                   |
| app-settings | アプリ全体設定       | テーマなどアプリ全体の設定を変更         |

### 遷移条件

- **ライブラリ未設定時** → SetupView（初回起動時は welcome ステップから開始）
- **ライブラリ追加** → SetupView（mode-select ステップから開始）
- **作品クリック** → viewer
- **サイドバーの設定ボタン** → settings
- **サイドバーの取り込みボタン** → import
- **サイドバーの一括取り込みボタン** → bulk-import（discover ステップから開始）
- **ドラッグ&ドロップ** → import または bulk-import（条件により分岐。詳細はインポート仕様書を参照）
- **設定画面の整合チェックから未登録フォルダ取り込み** → bulk-import
- **アプリ設定ボタン** → app-settings

### サイドバーの表示

サイドバーは以下の画面で表示される:

- library, settings, import, bulk-import

以下の画面では非表示:

- viewer, add-library, app-settings

## 4. リソース管理モード

ライブラリ作成時に選択するファイル管理方式。ライブラリごとに設定される。

### full モード

ライブラリルートフォルダを持ち、ファイルを集約管理する方式。

- ライブラリルートフォルダ配下にファイルを配置
- インポート時にファイルをコピーまたは移動
- ディレクトリテンプレートに従ってフォルダ構造を自動生成
- 作品削除時のファイル操作が可能（削除 / ゴミ箱へ移動 / 確認ダイアログ表示）
- 整合チェックで未登録フォルダの検出が可能

### metadata_only モード

ファイルを移動せず、パス情報のみをデータベースに記録する方式。

- ライブラリルートフォルダなし（path は null）
- ファイルは元の場所に留まり、パスだけを DB に記録
- ディレクトリテンプレートは無効
- 作品削除時は DB レコードのみ削除（ファイルには影響しない）
- 整合チェックでは孤立レコード（実体が存在しない作品）の検出のみ

## 5. 現状の制約

- **作品種別の制限**: works.type は現在 'folder' のみ実装されている。単体画像（'image'）、PDF（'pdf'）、アーカイブ（'archive'）はスキーマに定義されているが未対応。Issue #164 で単体画像対応を予定
- **プレイリスト未実装**: playlists / playlist_items テーブルはスキーマに存在するが、機能としては未実装
