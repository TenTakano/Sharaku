# Sharaku 仕様書 - 全体概要

## 1. アプリ概要

Sharaku はローカルの画像フォルダを「作品」として管理・閲覧するデスクトップアプリケーション。

ユーザーは「ライブラリ」を作成し、その中にフォルダを作品として登録する。登録した作品はグリッド形式で一覧表示され、ビューアでページ送りしながら閲覧できる。作品にはタグを付与してフィルタリングできる。

---

## 2. 主要な概念

### ライブラリ

作品を束ねる最上位の管理単位。複数のライブラリを作成でき、同時にアクティブにできるのは 1 つだけ。ライブラリごとにリソース管理モードや設定が独立している。

### 作品

ライブラリに属する個々の管理単位。現在は「フォルダ＝作品」として管理され、フォルダ内の画像がページとして扱われる。作品にはタイトル、作者、年、ジャンル、サークル、出典の 6 つのメタデータを持たせることができる。

DB スキーマ上は作品種別として 'image', 'pdf', 'archive', 'folder' の 4 種が定義されているが、実装上は 'folder' のみ使用している。

### タグ

作品に付与する分類ラベル。ライブラリごとに管理され、名前とカテゴリ（任意）を持つ。作品とタグは多対多の関係。

---

## 3. リソース管理モード

ライブラリ作成時に選択するファイル管理方式。ライブラリごとに設定される。

### full モード

ライブラリルートフォルダを持ち、ファイルを集約管理する方式。

- ライブラリルートフォルダ配下にファイルを配置
- インポート時にファイルをコピーまたは移動
- ディレクトリテンプレートに従ってフォルダ構造を自動生成
- 作品削除時のファイル操作が可能（削除 / ゴミ箱へ移動 / 確認ダイアログ表示）
- 整合チェックで未登録フォルダの検出が可能

### metadata_only モード

ファイルを移動せず、パス情報のみをデータベースに記録する方式。

- ライブラリルートフォルダなし
- ファイルは元の場所に留まり、パスだけを DB に記録
- ディレクトリテンプレートは無効
- 作品削除時は DB レコードのみ削除（ファイルには影響しない）
- 整合チェックでは孤立レコード（実体が存在しない作品）の検出のみ

---

## 4. 現状の制約

- **作品種別の制限**: 現在 'folder' のみ実装。単体画像（'image'）、PDF（'pdf'）、アーカイブ（'archive'）は未対応。Issue #164 で単体画像対応を予定
- **プレイリスト未実装**: スキーマに存在するが、機能としては未実装
