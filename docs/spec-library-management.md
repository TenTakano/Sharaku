# Sharaku 仕様書 - ライブラリ管理・設定

## 1. マルチライブラリ

複数のライブラリを作成・切り替えて使用できる。
同時にアクティブにできるライブラリは 1 つのみ（is_active フラグで管理）。

### 切り替え

サイドバーのドロップダウンでライブラリを切り替える。
切り替え時の動作:

- タグフィルタがリセットされる
- 作品グリッドが新しいライブラリの内容で再読み込みされる

### 削除

ライブラリ削除後の挙動は残存ライブラリの有無で分岐する。

| 条件                                                     | 動作                                   |
| -------------------------------------------------------- | -------------------------------------- |
| アクティブなライブラリを削除、他のライブラリが存在する   | 最古のライブラリが自動的にアクティブ化 |
| アクティブなライブラリを削除、他のライブラリが存在しない | セットアップ画面に遷移                 |
| 非アクティブなライブラリを削除                           | アクティブライブラリは変わらない       |

## 2. ライブラリ作成（SetupView）

ライブラリの初回作成と追加作成で開始ステップが異なる。

- **初回起動時**: welcome → select
- **追加作成時**: select から開始（welcome をスキップ）

### ステップ詳細

**ステップ 1: welcome**

アプリ名とキャッチコピーを表示する。「はじめる」ボタンで select ステップへ進む。

**ステップ 2: select**

ライブラリのディレクトリを選択する。ディレクトリの設定は必須ではなく、「フォルダを設定せずに続ける」ボタンで未設定のまま次へ進める。

- フォルダを選択した場合: 選択したフォルダ名がライブラリ名の初期値になる
- フォルダを設定せずに続ける場合: ライブラリ名は空の状態で入力を求める

フォルダの選択（またはスキップ）後にライブラリ名の入力欄が表示され、「作成」ボタンでライブラリを作成する。ライブラリはフォルダパス（未設定の場合は null）とともに DB に登録される。

---

## 3. ライブラリ設定（SettingsView）

サイドバーの設定ボタンから遷移する。アクティブなライブラリの設定を変更できる。

### 3.1 ライブラリルート

現在のライブラリの保存先ディレクトリを表示する（読み取り専用）。未設定の場合は「未設定」と表示される。

### 3.2 削除時のファイル処理

作品削除時にローカルファイルをどう扱うかを設定する。ライブラリ単位で設定可能。

| 設定値 | 動作                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------ |
| ask    | 削除時にダイアログを表示し、ユーザーに操作を選択させる（メタデータのみ削除 / ゴミ箱へ退避 / 完全削除） |
| trash  | ライブラリルート内の `.trash` フォルダに移動。同名ファイルが既に存在する場合はタイムスタンプを付与     |
| delete | ファイルを完全削除                                                                                     |

ライブラリにルートフォルダが設定されていない場合、trash は選択できない（`.trash` の配置先が存在しないため）。

### 3.3 一括取り込み

一括取り込み画面へ遷移するボタンを提供する。

### 3.4 ライブラリの削除

ライブラリの管理情報（作品・タグ等）を削除する。ファイルシステム上のファイルは削除されない。

- ギャップ: 16px
- カラム数: ビューポート幅に応じて動的に変化

### サムネイル

### ソート

| ソート項目 | 備考       |
| ---------- | ---------- |
| 作成日     | デフォルト |
| タイトル   | -          |

順序は昇順 / 降順を切り替え可能。

## 5. インポート

インポートとは、フォルダまたは画像ファイルを「作品」として DB に登録する処理。取り込み元のファイルは移動・コピーされず、元のパスのまま works.path に記録される（in-place 登録）。
2 つのインポート画面がある:

- **単一取り込み画面**: 1 つのフォルダまたは画像ファイルを 1 つの作品としてインポート
- **一括取り込み画面**: 複数のフォルダ・画像ファイルをまとめてインポート

### 5.1 ドラッグ&ドロップによるインポート起動

ライブラリ画面（library ビュー）でのみ有効。
ドロップ時にオーバーレイ「ここにフォルダをドロップして取り込み」を表示する。

**分岐条件**: ドロップされたパス数とパス種別により、以下のパターンに分岐する。

**パターン 1: 複数パス同時ドロップ**（paths.length > 1）

- 全パスの重複を除去（Set）
- 一括取り込み画面へ遷移（ドロップパスモード）

**パターン 2: 単一パス + ディレクトリ + サブフォルダに画像あり**

- パスの種別判定後、サブフォルダ内の画像有無を判定
- サブフォルダ判定: 対象ディレクトリのサブフォルダ（min_depth=1）を再帰的に走査し、直下に画像ファイルを持つサブフォルダが 1 つでもあれば true
- 一括取り込み画面へ遷移（ルートパスモード）

**パターン 3: 単一パス + ディレクトリ + サブフォルダに画像なし**

- 単一取り込み画面へ遷移（フォルダ取り込み）

**パターン 4: 単一パス + 画像ファイル**

- 単一取り込み画面へ遷移（画像取り込み）。単一取り込み画面には取り込み元パスと種別（画像）が渡され、メタデータ入力ステップへ直行する

**パターン 5: 単一パス + 対応形式以外（その他）**

- インポートは行わず、トースト（「対応していないファイル形式です」）でエラー表示する

### 5.2 単一取り込み画面

2 ステップ構成: 取り込み対象を選択 → メタデータ入力。

**取り込み対象を選択**:

- ドラッグ&ドロップからの遷移時はスキップ（初期パスと種別が設定済み）
- 手動時はラジオボタンで取り込み種別（「フォルダ（複数画像）」/「画像ファイル（1枚）」）を選択したうえで、ファイルダイアログでフォルダまたは画像ファイルを選択する
  - フォルダ選択時: ディレクトリ選択ダイアログ
  - 画像ファイル選択時: 対応画像拡張子（5.6 参照）でフィルタされたファイル選択ダイアログ

**メタデータ自動抽出（フォルダ名 / ファイル名パース）**:

フォルダ選択時はフォルダ名から、画像ファイル選択時はファイル名から拡張子を除いた部分から、作者名とタイトルを自動抽出する。以下の優先順でマッチを試みる:

| 優先度 | パターン                       | artist | title          |
| ------ | ------------------------------ | ------ | -------------- |
| 1      | `[Artist] Title`               | Artist | Title          |
| 2      | `Artist - Title`               | Artist | Title          |
| 3      | デフォルト（上記に該当しない） | 空     | フォルダ名全体 |

**メタデータ入力フィールド**:

以下の 6 項目を入力できる。タイトルのみ必須。

| フィールド   | 必須   | 型       |
| ------------ | ------ | -------- |
| タイトル     | はい   | テキスト |
| アーティスト | いいえ | テキスト |
| 年           | いいえ | 数値     |
| ジャンル     | いいえ | テキスト |
| サークル     | いいえ | テキスト |
| 出典         | いいえ | テキスト |

**登録先の表示**: コピー・移動は行わず、常に「元の場所に登録されます」と表示する。

### 5.3 一括取り込み画面

2 ステップ構成: フォルダ探索 → レビュー。

**起点**: 一括取り込み画面には 3 つの起点がある:

1. **ドラッグ&ドロップ（複数パス）** → ドロップパスモードで探索開始、レビューステップへ直行
2. **ドラッグ&ドロップ（単一パス、サブフォルダあり）** → ルートパスモードで探索開始、レビューステップへ直行
3. **サイドバーまたは設定画面の「一括取り込み」** → フォルダ探索ステップから開始（フォルダ選択ダイアログ）

**フォルダ探索**:

探索モードは 2 種類ある:

- **ルートパスモード**: 単一のルートディレクトリから再帰走査
- **ドロップパスモード**: ドロップされた複数パスのそれぞれを走査（ディレクトリはさらに再帰走査、画像ファイルはそのまま候補に追加）

進捗通知:

- 探索中: 50 フォルダごとに「N フォルダを探索中...」を通知
- 完了時: 「N 件を検出」（検出フォルダ数と検出画像数の合計）

**リーフフォルダ抽出ロジック**:

探索で見つかった「画像を含むフォルダ」の中から、最下層のもの（リーフフォルダ）のみを作品候補とする。

判定手順:

1. 画像を直接含むフォルダを全て候補として収集（各フォルダの直下にある画像ファイル数をカウント、再帰なし）
2. 各候補フォルダの全祖先パスを記録（ルートまで遡る）
3. 祖先パス集合に含まれるフォルダ = 中間フォルダ → スキップ対象
4. 祖先パス集合に含まれないフォルダ = リーフフォルダ → 作品候補

具体例:

```
root/
  ├─ chapter1/
  │  └─ photo.jpg        ← リーフ（作品候補）
  ├─ chapter2/
  │  └─ photo.jpg        ← リーフ（作品候補）
  └─ cover.jpg           ← root はスキップ（中間フォルダ）
```

この例では chapter1, chapter2 が作品候補となる。root は chapter1, chapter2 の祖先であるため中間フォルダとしてスキップされる。

**レビューステップ**:

テーブル形式で検出結果（フォルダ・画像混在）を一覧表示する。

| 列                              | 概要                                                      |
| ------------------------------- | --------------------------------------------------------- |
| チェックボックス                | インポート対象の選択/解除                                 |
| 種別                            | 「フォルダ」または「画像」                                |
| 名前                            | 検出されたフォルダ名またはファイル名                      |
| 画像数                          | フォルダ内の画像ファイル数（画像エントリは常に 1）        |
| タイトル                        | 編集可能。フォルダ名/ファイル名パースの結果がデフォルト値 |
| アーティスト                    | 編集可能。フォルダ名/ファイル名パースの結果がデフォルト値 |
| 年 / ジャンル / サークル / 出典 | 編集可能。常に 4 列とも表示される                         |
| 状態                            | 登録済み/未登録                                           |

選択状態のデフォルト:

- 登録済みフォルダ: 「登録済み」と表示、デフォルトで未選択
- 未登録フォルダ: デフォルトで選択済み

操作:

- タイトル・アーティスト・年・ジャンル・サークル・出典はインライン編集可能
- 全選択/全解除チェックボックス

### 5.4 インポート実行

**キュー方式**: インポートリクエストはキューに追加され、バックグラウンドワーカーが順次処理する。UI はブロックされず、ユーザーは他の操作を継続できる。

**in-place 登録**: 元のソースパス（フォルダまたは画像ファイルのパス）をそのまま works.path に記録する。ファイルのコピー・移動は行わない。同一ライブラリ内で同じパスが既に登録されている場合は `UNIQUE(library_id, path)` 制約違反としてエラーになる。

**サムネイル生成**: フォルダ型の作品は最初の画像から、画像型の作品はその画像自体から WebP 形式でサムネイルを生成する（最大 200x280px、品質 65）。

### 5.5 インポートバナー

画面下部に表示される進捗通知。インポートの状態遷移に応じて表示内容が変わる。

| 状態         | 表示内容                      |
| ------------ | ----------------------------- |
| キューに追加 | ジョブ ID 発行                |
| 処理開始     | 「取り込み中...」             |
| 進捗         | 「N/M」で現在の処理位置を表示 |
| 完了         | 「成功 N 件 / 失敗 M 件」     |

クローズ動作:

- **エラーなし**: 設定に応じて自動クローズ（0 / 1 / 3 / 5 秒）。0 は自動クローズなし
- **エラーあり**: 手動クローズのみ。エラー詳細をリスト表示

### 5.6 対応画像形式

jpg, jpeg, png, gif, webp, bmp（大文字小文字不問）

## 6. タグ

タグはライブラリに所属する。異なるライブラリ間でタグは共有されない。

各タグは name（必須）と category（任意）を持つ。ライブラリ内では name と category の組み合わせで一意となる。同じ name でも category が異なれば別のタグとして扱う。

作品とタグは多対多の関係を持ち、中間テーブルで関連付けられる。

### 6.1 削除時の振る舞い

- 作品を削除すると、その作品に紐づくタグ関連レコードも CASCADE で自動削除される
- タグを削除すると、そのタグに紐づく作品との関連レコードも CASCADE で自動削除される

いずれの場合も、関連先の実体（作品やタグそのもの）は削除されない。

### 6.2 タグの CRUD

- **作成**: name（必須）と category（任意）を指定して作成
- **更新**: 既存タグの name および category を変更可能
- **削除**: 確認ダイアログ後に削除。関連する作品との紐づけも CASCADE で削除
- **検索**: name に対する部分一致（LIKE）検索。検索結果は最大 50 件

### 6.3 タグの付与・除去

**付与**: ビューア画面のタグ入力欄から付与する。

- 入力中は既存タグがサジェストされる（部分一致検索）
- 既存タグを選択するとその作品に付与される
- 未登録の名前を入力した場合、新規タグとして作成したうえで付与される

**除去**: 作品に付いているタグはバッジとして表示される。バッジをクリックすると確認ダイアログが表示され、承認するとタグの紐づけが解除される。タグ自体は削除されない。

### 6.4 タグによるフィルタリング

タグフィルタは以下の 2 箇所から操作できる:

- **ツールバー**: ライブラリ画面上部のタグ入力欄から選択
- **サイドバー**: タグツリーのタグをクリックして追加/解除

タグを選択すると、そのタグを持つ作品のみが表示される。同じタグを再度選択するとフィルタが解除される。

**複数タグ選択時の検索モード**（タグ 2 つ以上で切り替えボタン表示）:

| モード | 動作                                   |
| ------ | -------------------------------------- |
| AND    | 選択した全てのタグを持つ作品のみ表示   |
| OR     | 選択したいずれかのタグを持つ作品を表示 |

### 6.5 サイドバーのタグツリー

サイドバーにはライブラリ内のタグがカテゴリ別にグループ化されて表示される。

- カテゴリが設定されているタグは、そのカテゴリ名のグループに表示される
- カテゴリが未設定のタグは "other" グループに表示される
- 各カテゴリは折りたたみ/展開が可能
- 現在フィルタ中のタグはハイライト表示される
- ライブラリ画面以外からタグをクリックした場合は、ライブラリ画面に遷移してからフィルタが適用される

## 7. 作品の削除

ライブラリ画面の作品グリッドでコンテキストメニュー（右クリック）から実行する。
同じコンテキストメニューには「プレイリストに追加」も含まれる（詳細は [spec-overview.md](spec-overview.md) のプレイリストを参照）。

### deleteFileAction による分岐

| deleteFileAction | 動作                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| ask              | 確認ダイアログで操作を選択（メタデータのみ削除 / ゴミ箱に退避 / 完全削除） |
| trash            | 確認後、ライブラリルート内の `.trash` フォルダへ移動                       |
| delete           | 確認後、ファイルを完全削除                                                 |

### パスの検証と削除処理

作品ファイルのパスは、削除実行前にディスク上に存在するかどうかのみを確認する（ライブラリルート配下かどうかのチェックは行わない）。取り込み元は in-place 登録のため、ライブラリルート外の任意のパスを指している場合がある。

- **delete**: 作品がフォルダの場合はディレクトリを再帰的に削除する。取り込み元ディレクトリそのものを対象にするため、アプリが登録していないファイル・サブディレクトリが含まれていても削除される
- **trash**: ライブラリルート内の `.trash` フォルダへ移動する。移動元とライブラリルートが別ファイルシステム上にある場合は、rename ではなくコピー後に元ファイルを削除するフォールバックで対応する。ライブラリにルートフォルダが設定されていない場合は実行できない

削除確認ダイアログには対象パスの絶対パスと、選択した操作に応じた注記（完全削除 / ゴミ箱への移動である旨）が表示される。

## 10. 現状の制約

- 一括取り込みのレビュー列は year/genre/circle/origin の固定 4 列のみ対応（テンプレートによる列の絞り込みは行わない）
- タグの一括付与（複数作品に同時にタグを付ける）は未対応
- インポート時にタグを指定する機能はない
- フォルダ型作品の完全削除は取り込み元ディレクトリ全体を再帰削除するため、アプリが登録していないファイルが含まれていても削除される
