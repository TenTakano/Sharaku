# Sharaku 仕様書 - ライブラリ管理・設定

## 1. マルチライブラリ

複数のライブラリを作成・切り替えて使用できる。
同時にアクティブにできるライブラリは 1 つのみ（is_active フラグで管理）。

### 切り替え

サイドバーのドロップダウンでライブラリを切り替える。
切り替え時の動作:

- タグフィルタがリセットされる
- 作品グリッドが新しいライブラリの内容で再読み込みされる

### 削除

ライブラリ削除後の挙動は残存ライブラリの有無で分岐する。

| 条件                                                     | 動作                                   |
| -------------------------------------------------------- | -------------------------------------- |
| アクティブなライブラリを削除、他のライブラリが存在する   | 最古のライブラリが自動的にアクティブ化 |
| アクティブなライブラリを削除、他のライブラリが存在しない | セットアップ画面に遷移                 |
| 非アクティブなライブラリを削除                           | アクティブライブラリは変わらない       |

## 2. ライブラリ作成（SetupView）

ライブラリの初回作成と追加作成で開始ステップが異なる。

- **初回起動時**: welcome → mode-select → 以降のステップ
- **追加作成時**: mode-select から開始（welcome をスキップ）

### ステップ詳細

**ステップ 1: mode-select**

リソース管理モードを選択する。

- full: ライブラリルートフォルダでファイルを集約管理
- metadata_only: ファイルを移動せず、パス情報のみ DB に記録

選択したモードによって後続のステップが変わる。

**ステップ 2: folder-select（full モードのみ）**

ライブラリルートとなるディレクトリを選択する。
metadata_only モードではスキップされる。

**ステップ 3: name-input**

ライブラリ名を入力する。

**ステップ 4: template-select（full モードのみ）**

ディレクトリテンプレートを選択する。
metadata_only モードではスキップされ、ここで作成が完了する。

- プリセット: `{artist}/{title}`, `{genre}/{artist}/{title}`, `{type}/{artist}/{title}`
- カスタム: 自由入力
- サンプルメタデータを使ったプレビュー表示あり（実際のパスがどうなるか確認可能）

### モード別フロー

**full モード**: welcome → mode-select → folder-select → name-input → template-select → 完了

**metadata_only モード**: welcome → mode-select → name-input → 完了

## 3. ライブラリ設定（SettingsView）

サイドバーの設定ボタンから遷移する。アクティブなライブラリの設定を変更できる。

### 3.1 リソース管理モード

full / metadata_only の切り替え。変更は即座に保存される。

### 3.2 ディレクトリテンプレート（full モードのみ）

作品フォルダの配置先パスを決めるテンプレート。
デフォルトは `{artist}/{title}`。

**トップレベルディレクトリ**: 実際の配置先は、ライブラリルート直下に作品種別ごとのトップレベルディレクトリを挟んだ `{ライブラリルート}/{works または pictures}/{テンプレート展開結果}` となる。folder 型は `works/`、image 型は `pictures/` が使われる。

**利用可能なプレースホルダー**:

| プレースホルダー | 概要                                       |
| ---------------- | ------------------------------------------ |
| {title}          | 作品タイトル                               |
| {artist}         | 作者                                       |
| {year}           | 年                                         |
| {genre}          | ジャンル                                   |
| {circle}         | サークル                                   |
| {origin}         | 出典                                       |
| {type}           | 作品タイプラベル（タイプラベル設定に依存） |

**バリデーション**:

以下のいずれかに該当するとエラーとなる。

- 空文字
- 未閉じプレースホルダー（例: `{title`）
- 未知のプレースホルダー
- {title} を含まない

**フォールバック**: メタデータの値が null または空文字の場合、"Unknown" に置換される。

**プレビュー表示**: サンプルメタデータを使って実際のパスをプレビュー表示する。

### 3.3 タイプラベル

{type} プレースホルダーで使用されるラベルをカスタマイズできる。

| 作品種別 | デフォルトラベル |
| -------- | ---------------- |
| image    | Image            |
| folder   | Folder           |

ライブラリ単位で設定可能。

### 3.4 削除時のファイル操作（full モードのみ）

作品削除時にファイルをどう扱うかを設定する。
metadata_only モードでは常に DB レコードのみ削除されるため、この設定は無効化される。

| 設定値 | 動作                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------- |
| ask    | 削除時にダイアログを表示し、ユーザーに操作を選択させる（ファイル操作なし / ゴミ箱 / 完全削除）     |
| trash  | ライブラリルート内の `.trash` フォルダに移動。同名ファイルが既に存在する場合はタイムスタンプを付与 |
| delete | ファイルを完全削除。ライブラリルート外のパスは拒否される（セキュリティ保護）                       |

## 4. ライブラリ画面（作品グリッド）

バーチャルスクロール（virtua/svelte）による効率的なグリッド表示。

### レイアウト

- カード幅: 固定 180px
- ギャップ: 16px
- カラム数: ビューポート幅に応じて動的に変化

### サムネイル

インメモリキャッシュ（Blob URL）で管理される。

### ソート

| ソート項目 | 備考       |
| ---------- | ---------- |
| 作成日     | デフォルト |
| タイトル   | -          |

順序は昇順 / 降順を切り替え可能。

## 5. インポート

インポートとは、フォルダを「作品」として DB に登録する処理。
2 つのインポート画面がある:

- **単一取り込み画面**: 1 つのフォルダを 1 つの作品としてインポート
- **一括取り込み画面**: 複数のフォルダをまとめてインポート

### 5.1 ドラッグ&ドロップによるインポート起動

ライブラリ画面（library ビュー）でのみ有効。
ドロップ時にオーバーレイ「ここにフォルダをドロップして取り込み」を表示する。

**パス種別判定**: ドロップされたパスは `classify_drop_path`（Rust 側 `scanner::classify_path`）でディレクトリ / 画像ファイル / その他のいずれかに判定される。判定結果はディレクトリ / 画像ファイルどちらであってもそのままのパスが使われ、親ディレクトリへの変換は行われない。

**分岐条件**: ドロップされたパス数とパス種別により、以下のパターンに分岐する。

**パターン 1: 複数パス同時ドロップ**（paths.length > 1）

- 全パスの重複を除去（Set）
- 一括取り込み画面へ遷移（ドロップパスモード）

**パターン 2: 単一パス + ディレクトリ + サブフォルダに画像あり**

- パスの種別判定後、サブフォルダ内の画像有無を判定
- サブフォルダ判定: 対象ディレクトリのサブフォルダ（min_depth=1）を再帰的に走査し、直下に画像ファイルを持つサブフォルダが 1 つでもあれば true
- 一括取り込み画面へ遷移（ルートパスモード）

**パターン 3: 単一パス + ディレクトリ + サブフォルダに画像なし**

- 単一取り込み画面へ遷移（フォルダ取り込み）

**パターン 4: 単一パス + 画像ファイル**

- 単一取り込み画面へ遷移（画像取り込み）。単一取り込み画面には取り込み元パスと種別（画像）が渡され、メタデータ入力ステップへ直行する

**パターン 5: 単一パス + 対応形式以外（その他）**

- インポートは行わず、トースト（「対応していないファイル形式です」）でエラー表示する

### 5.2 単一取り込み画面

2 ステップ構成: 取り込み対象を選択 → メタデータ入力。

**取り込み対象を選択**:

- ドラッグ&ドロップからの遷移時はスキップ（初期パスと種別が設定済み）
- 手動時はラジオボタンで取り込み種別（「フォルダ（複数画像）」/「画像ファイル（1枚）」）を選択したうえで、ファイルダイアログでフォルダまたは画像ファイルを選択する
  - フォルダ選択時: ディレクトリ選択ダイアログ
  - 画像ファイル選択時: 対応画像拡張子（5.6 参照）でフィルタされたファイル選択ダイアログ

**メタデータ自動抽出（フォルダ名 / ファイル名パース）**:

フォルダ選択時はフォルダ名から、画像ファイル選択時はファイル名から拡張子を除いた部分から、作者名とタイトルを自動抽出する。以下の優先順でマッチを試みる:

| 優先度 | パターン                       | artist | title          |
| ------ | ------------------------------ | ------ | -------------- |
| 1      | `[Artist] Title`               | Artist | Title          |
| 2      | `Artist - Title`               | Artist | Title          |
| 3      | デフォルト（上記に該当しない） | 空     | フォルダ名全体 |

**メタデータ入力フィールド**:

以下の 6 項目を入力できる。タイトルのみ必須。

| フィールド   | 必須   | 型       |
| ------------ | ------ | -------- |
| タイトル     | はい   | テキスト |
| アーティスト | いいえ | テキスト |
| 年           | いいえ | 数値     |
| ジャンル     | いいえ | テキスト |
| サークル     | いいえ | テキスト |
| 出典         | いいえ | テキスト |

**resource_mode による差異**:

- full モード: コピー/移動の選択 UI を表示。配置先パスのプレビューを表示（ディレクトリテンプレート適用結果）。メタデータ変更時に 300ms デバウンスでプレビューを更新
- metadata_only モード: モード選択 UI なし。「元の場所に登録されます」と表示

### 5.3 一括取り込み画面

2 ステップ構成: フォルダ探索 → レビュー。

**起点**: 一括取り込み画面には 4 つの起点がある:

1. **ドラッグ&ドロップ（複数パス）** → ドロップパスモードで探索開始、レビューステップへ直行
2. **ドラッグ&ドロップ（単一パス、サブフォルダあり）** → ルートパスモードで探索開始、レビューステップへ直行
3. **サイドバーの「一括取り込み」** → フォルダ探索ステップから開始（フォルダ選択ダイアログ）
4. **設定画面の整合チェック** → 未登録フォルダ情報を直接レビューステップへ渡す（探索スキップ）

**フォルダ探索**:

探索モードは 2 種類ある:

- **ルートパスモード**: 単一のルートディレクトリから再帰走査
- **ドロップパスモード**: 複数のルートディレクトリを走査。ルートには画像ファイルも混在でき、画像ファイルのルートはフォルダ探索とは別に単体画像の取り込み候補として扱われる。フォルダパス・画像パスそれぞれで重複排除（seen_paths / seen_image_paths）

進捗通知:

- 探索中: 50 フォルダごとに「N フォルダを探索中...」を通知
- 完了時: 「N 件を検出」（検出フォルダ数と検出画像数の合計）

**リーフフォルダ抽出ロジック**:

探索で見つかった「画像を含むフォルダ」の中から、最下層のもの（リーフフォルダ）のみを作品候補とする。

判定手順:

1. 画像を直接含むフォルダを全て候補として収集（各フォルダの直下にある画像ファイル数をカウント、再帰なし）
2. 各候補フォルダの全祖先パスを記録（ルートまで遡る）
3. 祖先パス集合に含まれるフォルダ = 中間フォルダ → スキップ対象
4. 祖先パス集合に含まれないフォルダ = リーフフォルダ → 作品候補

具体例:

```
root/
  ├─ chapter1/
  │  └─ photo.jpg        ← リーフ（作品候補）
  ├─ chapter2/
  │  └─ photo.jpg        ← リーフ（作品候補）
  └─ cover.jpg           ← root はスキップ（中間フォルダ）
```

この例では chapter1, chapter2 が作品候補となる。root は chapter1, chapter2 の祖先であるため中間フォルダとしてスキップされる。

スキップされたフォルダは、レビューステップ上部に件数と合計画像数（「N 件の中間フォルダにある M 枚の画像はスキップされました」）で警告表示され、トグルで各フォルダ名・パス・画像数の詳細一覧を表示できる。

**レビューステップ**:

テーブル形式で検出結果（フォルダ・画像混在）を一覧表示する。

| 列               | 概要                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| チェックボックス | インポート対象の選択/解除                                                                                              |
| 種別             | 「フォルダ」または「画像」                                                                                             |
| 名前             | 検出されたフォルダ名またはファイル名                                                                                   |
| 画像数           | フォルダ内の画像ファイル数（画像エントリは常に 1）                                                                     |
| タイトル         | 編集可能。フォルダ名/ファイル名パースの結果がデフォルト値                                                              |
| アーティスト     | 編集可能。フォルダ名/ファイル名パースの結果がデフォルト値                                                              |
| （動的列）       | 編集可能。ライブラリのディレクトリテンプレートで使用中の year/genre/circle/origin に対応する列のみ追加表示（下記参照） |
| 状態             | 登録済み/未登録                                                                                                        |

選択状態のデフォルト:

- 登録済みフォルダ: 「登録済み」と表示、デフォルトで未選択
- 未登録フォルダ: デフォルトで選択済み

操作:

- タイトル・アーティストはインライン編集可能
- 全選択/全解除チェックボックス
- full モード時: コピー/移動の選択
- year, genre, circle, origin は、ライブラリのディレクトリテンプレートで使用中のプレースホルダーに対応する列のみテーブルに動的追加され、行ごとにインライン編集可能。ディレクトリテンプレートが未設定、または該当プレースホルダーが使われていない場合はその列を表示せず入力不可（null で登録）。year は数値変換できない入力は null として送信される

### 5.4 インポート実行

**キュー方式**: インポートリクエストはキューに追加され、バックグラウンドワーカーが順次処理する。UI はブロックされず、ユーザーは他の操作を継続できる。

**resource_mode による分岐**:

- metadata_only モード: 元のフォルダパスをそのまま works.path に記録。ファイル操作なし
- full モード:
  1. ディレクトリテンプレートとメタデータから配置先パスを生成（ライブラリルート直下に作品種別のトップレベルディレクトリ `works/` または `pictures/` を付与したうえでテンプレートを展開する）
  2. パス重複時は `_0001` 形式のサフィックスを付与して一意にする
  3. 配置先ディレクトリを作成
  4. 画像ファイルをコピー
  5. works レコードを作成
  6. move モードの場合、元ファイルを削除
  7. エラー時: コピー先ディレクトリを削除してロールバック

**サムネイル生成**: フォルダ内の最初の画像から WebP 形式でサムネイルを生成する（最大 200x280px、品質 65）。

### 5.5 インポートバナー

画面下部に表示される進捗通知。インポートの状態遷移に応じて表示内容が変わる。

| 状態         | 表示内容                      |
| ------------ | ----------------------------- |
| キューに追加 | ジョブ ID 発行                |
| 処理開始     | 「取り込み中...」             |
| 進捗         | 「N/M」で現在の処理位置を表示 |
| 完了         | 「成功 N 件 / 失敗 M 件」     |

クローズ動作:

- **エラーなし**: 設定に応じて自動クローズ（0 / 1 / 3 / 5 秒）。0 は自動クローズなし
- **エラーあり**: 手動クローズのみ。エラー詳細をリスト表示

### 5.6 対応画像形式

jpg, jpeg, png, gif, webp, bmp（大文字小文字不問）

## 6. タグ

タグはライブラリに所属する。異なるライブラリ間でタグは共有されない。

各タグは name（必須）と category（任意）を持つ。ライブラリ内では name と category の組み合わせで一意となる。同じ name でも category が異なれば別のタグとして扱う。

作品とタグは多対多の関係を持ち、中間テーブルで関連付けられる。

### 6.1 削除時の振る舞い

- 作品を削除すると、その作品に紐づくタグ関連レコードも CASCADE で自動削除される
- タグを削除すると、そのタグに紐づく作品との関連レコードも CASCADE で自動削除される

いずれの場合も、関連先の実体（作品やタグそのもの）は削除されない。

### 6.2 タグの CRUD

- **作成**: name（必須）と category（任意）を指定して作成
- **更新**: 既存タグの name および category を変更可能
- **削除**: 確認ダイアログ後に削除。関連する作品との紐づけも CASCADE で削除
- **検索**: name に対する部分一致（LIKE）検索。検索結果は最大 50 件

### 6.3 タグの付与・除去

**付与**: ビューア画面のタグ入力欄から付与する。

- 入力中は既存タグがサジェストされる（部分一致検索）
- 既存タグを選択するとその作品に付与される
- 未登録の名前を入力した場合、新規タグとして作成したうえで付与される

**除去**: 作品に付いているタグはバッジとして表示される。バッジをクリックすると確認ダイアログが表示され、承認するとタグの紐づけが解除される。タグ自体は削除されない。

### 6.4 タグによるフィルタリング

タグフィルタは以下の 2 箇所から操作できる:

- **ツールバー**: ライブラリ画面上部のタグ入力欄から選択
- **サイドバー**: タグツリーのタグをクリックして追加/解除

タグを選択すると、そのタグを持つ作品のみが表示される。同じタグを再度選択するとフィルタが解除される。

**複数タグ選択時の検索モード**（タグ 2 つ以上で切り替えボタン表示）:

| モード | 動作                                   |
| ------ | -------------------------------------- |
| AND    | 選択した全てのタグを持つ作品のみ表示   |
| OR     | 選択したいずれかのタグを持つ作品を表示 |

### 6.5 サイドバーのタグツリー

サイドバーにはライブラリ内のタグがカテゴリ別にグループ化されて表示される。

- カテゴリが設定されているタグは、そのカテゴリ名のグループに表示される
- カテゴリが未設定のタグは "other" グループに表示される
- 各カテゴリは折りたたみ/展開が可能
- 現在フィルタ中のタグはハイライト表示される
- ライブラリ画面以外からタグをクリックした場合は、ライブラリ画面に遷移してからフィルタが適用される

## 7. 作品の削除

ライブラリ画面の作品グリッドでコンテキストメニュー（右クリック）から実行する。
同じコンテキストメニューには「プレイリストに追加」も含まれる（詳細は [spec-overview.md](spec-overview.md) のプレイリストを参照）。

### resource_mode と deleteFileAction の組み合わせ

| resource_mode | deleteFileAction | 動作                                                               |
| ------------- | ---------------- | ------------------------------------------------------------------ |
| metadata_only | （任意）         | DB レコードのみ削除                                                |
| full          | ask              | 確認ダイアログで操作を選択（ファイル操作なし / ゴミ箱 / 完全削除） |
| full          | trash            | 確認後、`.trash` フォルダに移動                                    |
| full          | delete           | 確認後、ファイルを完全削除                                         |

### セキュリティ制約

ライブラリルート外のパスを持つ作品は、ファイル操作（trash / delete）を拒否する。
この場合は DB レコードのみ削除可能。

## 9. ファイル再配置（Relocation）

ディレクトリテンプレートを変更した際、既存作品のフォルダパスを新テンプレートに合わせて移動する機能。
full モードのみ有効。folder 型の作品のみ対象。新パスは 3.2 と同様に `works/` トップレベルディレクトリを含む形で算出される。

既存作品の現在パスが「トップレベルディレクトリを付与する前」の旧形式のテンプレート展開結果と一致する場合は、再配置対象から除外される（トップレベルディレクトリ導入前に作成された作品を、テンプレート値を変更していないのに一括移動させないための互換動作）。

### フロー

1. テンプレート変更を保存
2. 再配置が必要な作品が存在する場合、プレビューを表示（旧パス → 新パスの一覧）
3. ユーザーが実行を確認
4. 作品ごとに以下の手順で処理:
   - コピー先ディレクトリを作成
   - 画像ファイルをコピー
   - DB の path を更新
   - 旧ファイルを削除
   - 空になった祖先ディレクトリを除去

### パス重複時の扱い

コピー先パスが既に存在する場合、`_0001` 形式のサフィックスを付与して一意にする。

### エラー時の扱い

コピー先を削除（ロールバック）し、その作品をスキップして次の作品の処理を継続する。
全体の処理は中断しない。

### 進捗通知

| 段階   | 通知内容                                  |
| ------ | ----------------------------------------- |
| 開始   | started                                   |
| 処理中 | moving（作品ごとに通知）                  |
| 完了   | completed（成功 / スキップ / 失敗の件数） |

## 10. 整合チェック（Integrity Check）

ライブラリの DB レコードとファイルシステムの整合性を確認する機能。
設定画面から実行する。2 フェーズで構成される。

### フェーズ 1: 孤立レコード検出

全 works の path が実際に存在するかを確認する。

| 作品種別     | 存在判定                           |
| ------------ | ---------------------------------- |
| folder 型    | パスがディレクトリとして存在するか |
| 非 folder 型 | パスがファイルとして存在するか     |

進捗通知: checked / total 形式。検出された孤立レコードは一括削除が可能。

### フェーズ 2: 未登録フォルダ検出（full モードのみ）

ライブラリルートを再帰走査し、DB に未登録のフォルダを検出する。

- `.trash` ディレクトリは走査対象外
- 画像を直接含むフォルダで、DB に未登録のものを検出

検出された未登録フォルダは一括取り込み画面に渡してインポート可能。

## 12. 現状の制約

- 一括取り込みの year, genre, circle, origin 列は、ライブラリのディレクトリテンプレートで使用中のプレースホルダーに対応するもののみ表示される。テンプレート未設定時やプレースホルダー未使用時はその項目を入力できない（Issue #93）
- タグの一括付与（複数作品に同時にタグを付ける）は未対応
- インポート時にタグを指定する機能はない
- 整合チェックの未登録フォルダ検出は full モードのみ対応
- ファイル再配置は folder 型の作品のみ対象
